# MG-30 Tone Master

分析吉他音檔 → 推估用了哪些效果 → 產生 **NUX MG-30** 的 Patch 設定 (型號、旋鈕數值、串/並聯)。

純 Python，只靠 NumPy / SciPy 的訊號處理，沒有機器學習模型、不需要 GPU、不需要上網。

## 安裝

需要 Python 3.9 以上 (3.13 已測試)。建議用虛擬環境：

```bash
git clone <repo-url>
cd mg30_tone_master
python -m venv .venv
# Windows:  .venv\Scripts\activate
# macOS / Linux:  source .venv/bin/activate
pip install -r requirements.txt
```

只有三個相依套件：numpy、scipy、soundfile。soundfile 的 wheel 自帶 libsndfile，wav / flac / mp3 / ogg 不需要另外裝任何解碼器。

要讀 m4a / aac / mp4 時再多裝 ffmpeg (會自動下載一個獨立的 ffmpeg 執行檔，不需要系統安裝)：

```bash
pip install -r requirements-optional.txt
```

安裝完可以先跑一次自我測試確認環境正常：

```bash
python make_test_audio.py && python run_tests.py
```

## 使用

```bash
# 1. 分析目標音色
python mg30_tone.py 目標.wav

# 只分析其中一段 (例如 1:05 開始的 20 秒 solo)
python mg30_tone.py 歌曲.mp3 --start 65 --length 20

# 2. 用 MG-30 照建議設定錄一段同樣的樂句，再比對 → 得到修正建議
python mg30_tone.py 目標.wav --compare 我的MG30錄音.wav
```

輸出 `<檔名>_mg30.md` (設定報告) 與 `<檔名>_mg30.json` (完整數據)。支援 wav / flac / mp3 / ogg (裝了 imageio-ffmpeg 後也支援 m4a / aac / mp4)。

### 校正 (吉他不同、聽起來不像時)

```bash
# 加上吉他型號 → 報告多出拾音器段位 / Alter Switch / Tone 旋鈕建議
python mg30_tone.py 目標.wav --guitar azes40

# 比對：目標取 0~30 秒，你的錄音取 2~32 秒；報告會直接列出「原本 → 改成」的旋鈕表
python mg30_tone.py 目標.wav --start 0 --length 30 --compare 我的錄音.wav --compare-start 2 --guitar azes40

# 第二輪：以上一輪輸出的 json (含校正後設定) 為基準，再錄一次再比
python mg30_tone.py 目標.wav --start 0 --length 30 --compare 我的錄音2.wav --preset 目標_mg30.json
```

- 每輪只修正 80% 的差距，避免調過頭；通常 2~3 輪會收斂。
- 若「每一段」比對結果都偏同一個方向 (例如都缺低頻)，那是吉他造成的，報告會給 **Global PRE EQ** 的補償值，一次套用到所有 Patch。
- 錄音方式：MG-30 接 USB，GLOBAL SETTING → USB AUDIO → ROUTING 設 **NORMAL**、REC Level 0 dB，用錄音軟體選 MG-30 為輸入。不要用麥克風收音箱/喇叭 (會混入房間聲音)。

## 原理

整個流程分成三層：**特徵分析** (`features.py`) 把音檔變成一組數字、**設定推薦** (`recommend.py`) 用規則把數字對應到 MG-30 的型號與旋鈕、**比對校正** (`calibrate.py`) 用「目標 vs 你的錄音」的差異直接修正旋鈕值。

```
音檔 ─→ 前處理 ─→ STFT ─→ 音量曲線 / 起音點 / 持續音段
                              │
          ┌───────┬───────┬───┴───┬────────┬────────┬─────────┐
        速度    破音    頻響    動態     延遲     殘響    調變/哇音
          └───────┴───────┴───┬───┴────────┴────────┴─────────┘
                              ▼
                    特徵字典 (每項附 confidence)
                              │
                  recommend.build_preset()  ←  mg30_db (型號清單 / 參數)
                              │
                     Patch 設定 (.md / .json)
                              │
        (--compare) features.compare() → calibrate.calibrate() → 修正後的旋鈕表
```

每個偵測器都是**啟發式的訊號處理**，而不是訓練出來的模型。好處是結果可以解釋 (報告的「判斷依據」欄會寫出為什麼)，壞處是對於完整混音 (有鼓、貝斯、人聲) 會失準，所以最準的素材是單獨的吉他音軌。

### 1. 前處理

1. 讀檔後轉成 44.1 kHz (48 kHz 保留)，取最多 90 秒，裁掉頭尾低於峰值 60 dB 的靜音，峰值正規化到 0.89。
2. 單聲道混音做 STFT (Hann 窗、2048 點、hop 512，約每 11.6 ms 一個 frame)。之後所有偵測器共用這個頻譜圖 `P`。
3. 算出每個 frame 的**音量曲線** (dB)，以 5% 分位數當**底噪**。連續演奏沒有空白時 5% 分位數其實是演奏音量，所以門檻另外用 40% 分位數封頂。
4. **起音點 (onset)**：對 log 壓縮後的頻譜取正向差分加總 (spectral flux)，用中位數濾波當自適應門檻找峰值。
5. **持續音段**：起音後 120 ms 以外、而且還在演奏中的連續區間，長度至少 0.35 秒。調變類效果 (Tremolo / Phaser / Chorus / Wah) 都只在這些區段觀察，因為「同一個音持續中」頻譜或音高仍在變，才是效果器造成的。

### 2. 速度 (BPM)

對 spectral flux 做自相關，在 60~200 BPM 掃描，把一拍、兩拍、四拍位置的自相關值加權相加；再乘上以 115 BPM 為中心的常態分佈先驗 (偏好常見速度)。信心值看最佳分數相對其他候選分數的突出程度。BPM 只拿來把延遲時間換算成拍值 (1/4、1/8D、1/8…)，誤差 5% 內才會標示。

### 3. 破音程度

只取每個起音點後的 1~4 個 frame 來看，因為那裡原音最強、殘響與延遲的影響最小。四個指標：

| 指標 | 意義 | 乾淨 → 重破音 |
|---|---|---|
| 峰值因數 (crest factor) | 峰值 / RMS | 10 dB → 5 dB (削波讓波形變方) |
| 頻譜平坦度 (150~6k Hz) | 幾何平均 / 算術平均 | −30 dB → −18 dB (諧波填滿頻譜) |
| 高頻諧波比 | 1.5~5 kHz 對 100~800 Hz 的能量比 | −15 dB → −6 dB |
| 延音衰減 | 起音峰值到 0.4 秒後掉了多少 | 10 dB → 1 dB (破音壓縮延音) |

各項線性映射到 0~1 後加權平均 (峰值因數權重最大 0.40)，得到 0~1 的「破音分數」，再切成 clean / edge_of_breakup / crunch / high_gain / very_high_gain 五級。若偵測到延遲或殘響，平坦度與延音兩項的權重會降低，因為空間效果本身也會讓頻譜變平、延音變長。

另外有一條 **Fuzz** 特徵：平坦度 > −9.5 dB 且峰值因數 < 6 dB 且分數 > 0.8，會改推 Big Muff 類的 EFX 搭配低增益音箱。

### 4. 頻率響應

以 400~1200 Hz 中頻為基準，算低頻 (80~250)、低中 (250~500)、中高 (1.2~2.5k)、高頻 (2~5k)、空氣感 (5~9k) 的相對能量，以及 MG-30 6-Band EQ 六個中心頻率 (100 / 220 / 500 / 1.2k / 2.6k / 6.4k) 各 1/3 八度寬的相對能量。

推薦時把這些值和一條**中性參考曲線** `REF` (一般「吉他 → 音箱 → 箱體」錄音的平均頻譜) 相減，差值乘上斜率 (約 3.5 單位 / dB) 變成 BASS / MIDDLE / TREBLE / PRESENCE 旋鈕的偏移；旋鈕夾在 15~85，避免粗估就推到極端。音箱旋鈕吃不下的剩餘差異 (任一頻段 ≥ 2.5 dB) 才開 6-Band EQ。

### 5. 動態 / 壓縮

動態範圍 = 演奏中音量的 95% 分位數 − 20% 分位數 (20 dB → 6 dB 對應壓縮分數 0 → 1)，再和「起音峰值比音體高多少」(8 dB → 1.5 dB) 各佔一半。只有 clean / 微破 才會建議 CMP；有延遲或殘響時門檻提高 (0.55 → 0.8)，因為尾音也會把動態範圍壓小。

### 6. 延遲 (Delay)

這是最複雜的偵測器。核心想法：**回音會讓訊號和「自己延遲 L 秒後」高度相關**，所以自相關函數在 lag = L 會出現尖峰。但直接做自相關會被音符本身的週期性 (基頻、和弦音的共同週期) 淹沒，因此：

1. **頻譜白化** (類似 GCC-PHAT)：互功率譜除以平滑後的功率譜，壓掉音高造成的週期性，只留下時間結構。只用 150~1500 Hz。
2. **分塊取中位數**：音檔切成數個重疊區塊各自計算，再取中位數。真正的回音在每個區塊都在同一個 lag；某個音符的週期只會出現在部分區塊。
3. **孤立峰值搜尋**：在 60 ms ~ 1.6 s 找最高峰，並要求它「孤立」(2~15 ms 外的鄰近區域沒有相近高度的峰)。和弦音的共同週期也會產生峰值，但那種旁邊會有一整排。判定條件：相關係數 > 0.05、對中位數的 z 分數 > 10、孤立度 > 1.6。
4. **備援**：若沒找到，改用 80~400 Hz 相關函數的 Hilbert 包絡再找一次。磁帶 / 調變延遲的時間抖動會讓尖峰互相抵消，取包絡可以容忍。
5. **半拍檢查**：若 L/2 也有 ≥ 60% 高的峰，真正的延遲時間是 L/2 (找到的是第二次重複)。
6. **音量與回授**：取 L、2L、3L 三處的峰值，對「原音 + a·fb^k 衰減回音」的理論自相關做網格搜尋，解出第一次回音的音量 `a` 與回授 `fb`。
7. **類型判斷**：
   - 另外在 2~6 kHz 做一次相關，比較 L 處峰值和低頻的比例 → 低於 0.6 表示回音高頻被砍 → **Analog / Tape**。
   - 峰值半高寬 > 1.5 ms 表示時間在抖 → **Tape** (暗) 或 **Modulation** (亮)。
   - 立體聲時算左右聲道的互相關；若 L 處的互相關比自相關高 30% 以上，表示回音在對側聲道 → **Ping-Pong**。
   - 其餘 → **Digital**。

### 7. 殘響 (Reverb)

殘響只能在「演奏停下來」的地方量，所以先在音量曲線上找**切音點**：80 ms 內掉了 ≥ 4 dB、且不是新的起音。從那裡開始沿著尾音往後追，直到音量回升超過 6 dB (有新的音) 或接近底噪。

對每段尾音的前 1 秒 (Early Decay) 做 dB 對時間的線性回歸，斜率換算成 **RT60 = −60 / 斜率**；殘響量 = 切音前音量 − 尾音起點音量。多段尾音取中位數。真正的殘響只會單調衰減，中途回升 > 3 dB 的段落 (Tremolo、拍頻、繼續演奏) 會被丟掉。

**和延遲同時存在時**，先用 minimum filter (寬度 ≈ 1.1 倍延遲時間) 取「回音與回音之間」的下包絡，再量衰減；但延遲回授會把尾音撐住，所以 RT60 和回授無法完全分開，報告會標示「可能有」並給保守值 (RT60 / 4，夾在 0.8~3 秒)、RVB LEVEL 壓到 30 以下。

RT60 < 0.8 秒 → Room；0.8~1.8 → Plate；> 1.8 → Hall。若 Fender 類音箱搭 0.6~2.5 秒殘響會另外建議 Spring。殘響較大 (RT60 > 1.5 秒或位準 > −14 dB) 且同時有延遲時，建議 DLY 與 RVB **並聯**，讓回音不被殘響糊掉。

### 8. Phaser / Flanger / 哇音

這三種效果都是「頻譜形狀隨時間移動」，差別在移動的方式：

1. 把 250~6000 Hz 分成 20 個對數頻帶，算每個 frame 的**頻譜形狀** (各頻帶相對總能量的 dB)，在每個持續音段內去趨勢。
2. 對所有段的形狀變化做 SVD，取第一主成分 (變化最大的方向)。主成分的時間序列若用 Welch 功率譜在 0.1~8 Hz 找到明顯的週期 (突出度 > 8) 且整體變化量 > 3 dB → **週期性掃動**。
   - 看第一主成分的 loading 在 20 個頻帶之間變號幾次：≥ 6 次表示有多個梳狀凹口在移動 → **Flanger**；否則 → **Phaser**。Crunch 音色、速率 0.5~4 Hz、幅度大時改推 **U-Vibe**。
3. **哇音**：在 300~3000 Hz 以 1/24 八度解析度追蹤每個 frame 最突出的**共振峰**。10%~90% 分位的移動範圍 > 0.7 個八度、而且移動是平滑的 (相鄰 frame 跳動 > 1/4 八度的比例 < 6%) → 哇音踏板。和弦諧波的峰值會跳來跳去，不會被誤判。
   - 共振峰位置與音量曲線的相關係數 > 0.5 (越大聲濾波器開越多) → **Auto Wah** (EFX Touch Wah)；否則 → **踏板** (WAH Cry BB)。
4. **半踩哇 (cocked wah)**：長時間平均頻譜中，細平滑減粗平滑後若有 > 12 dB 的窄峰落在 400~2500 Hz → 用 EQ 的 Para EQ 模擬那個共振峰。

### 9. Tremolo

在持續音段內取音量曲線 (dB)，去趨勢後高通 1.5 Hz 去掉自然衰減，用 Welch 功率譜在 2~15 Hz 找峰值 (突出度 > 6)。再用每一段在該週期的自相關驗證 (中位數 > 0.3，避免單一段的巧合)。深度 = 帶通到該頻率附近後的峰對峰值 (> 2 dB 才算)。

### 10. Chorus / Vibrato

兩者都是音高在週期性擺動，差別在深度與是否混合原音：

1. 每個持續音段找 150~1500 Hz 最強的分音，用 **phase vocoder** (相鄰 frame 的相位差) 算出逐 frame 的瞬時頻率，換算成相對中位數的 cents 偏移。
2. 深度 = 去趨勢後的峰對峰 cents 值；速率從夠長 (≥ 1.2 秒) 的段落做 FFT 取得。
3. **每個音的深度要差不多** (一致性 > 0.6、至少 4 段) 才算效果器，因為手指揉弦只會出現在部分音、深度也不固定。
4. 深度 > 30 cents → **Vibrato** (Vibrator)；6~30 cents → **Chorus**。立體聲寬度 > 0.15 選 St. Chorus，Jazz Clean 音箱搭 CE-1，其餘 CE-2。

### 11. 立體聲寬度

寬度 = 1 − 左右聲道相關係數。用來判斷立體聲 Chorus 與 Ping-Pong 延遲。

### 12. 特徵 → MG-30 設定

`recommend.build_preset()` 是一組手寫規則，大致邏輯：

- **AMP**：先依破音等級選音箱家族 (clean → Fender 類；微破 / Crunch → Vox / Tweed / Plexi；High Gain → JCM800 / SLO / Friedman；Metal → Rectifier / VH4)，再用「高頻比參考亮多少」和「中頻比參考凹多少」在家族內挑型號，並列出 2 個備選。
- **GAIN 旋鈕**：每台音箱有一組 `AMP_GAIN_RANGE` (GAIN 0 → 100 大約涵蓋的破音分數範圍)，把量到的分數在這個範圍內線性內插。推了 EFX 時分數會先扣掉 EFX 貢獻的部分。
- **EFX**：High Gain 以上固定推 Tube Screamer 當緊縮推進 (Drive 低、Level 高)；Crunch 且中頻突出 → TS 推音箱；微破且壓縮分數高 → Blues Driver；Fuzz 特徵 → Big Muff。
- **IR**：跟音箱走原廠配對箱體；麥克風依高頻量選 R121 (暗) / SM57 / C414 (亮)，MIC AXIS 同理；LO CUT / HI CUT 依低頻與空氣感的量決定。
- **MOD**：一個 Patch 只有一個 MOD block，同時偵測到多種時依「Tremolo > Vibrato > Chorus > Flanger > Phaser」的優先序取一個，其餘寫在注意事項。RATE 旋鈕用對數映射 Hz → 0~100，並標「≈」。
- **DLY**：類型決定型號 (Digital / Analog / Tape Echo / Modulation / Pan Delay)，時間直接給 ms 並換算拍值，LEVEL ≈ 第一次回音音量 × 90，FEEDBACK ≈ 回授 × 100。
- **GATE**：High Gain 以上必開，底噪高時 SENSITIVITY 高一點；Crunch 輕度。
- **串/並聯**：見上方殘響一節。

旋鈕 ↔ 物理量 (Hz、秒) 的對照官方沒有公開，這些換算都是近似值，所以才有下一步的比對校正。

### 13. 比對校正 (`--compare`)

對目標與你的錄音各跑一次完整分析，`features.compare()` 算差值：

- 6-Band 六個頻段的 dB 差。
- 破音「核心分數」差：這裡**只用峰值因數與平坦度**，不用高頻諧波比，因為後者會被 EQ 和吉他本身影響。
- 壓縮分數差、延遲的時間 / 音量 / 回授差、殘響的 RT60 / 位準差 (兩邊 RT60 都確定時才比)。

`calibrate.calibrate()` 再把差值乘上 **0.8** 套回上一輪的設定：EQ 直接加 dB (半格進位、夾 ±12)、AMP GAIN 加 差值 × 150、CMP SUSTAIN 加 差值 × 60、DLY LEVEL 依 dB 差換算成倍率、RVB LEVEL 加 dB 差 × 2.5、DECAY 加 秒差 × 20。GAIN 若會超過 85 就改加 EFX 的 LEVEL (用前級推)。只修 80% 是為了避免過衝，重複 2~3 輪會收斂。

最後把六個頻段的差平均成低 / 中 / 高三段，給 **Global PRE EQ** 的建議值：如果每首歌比下來都偏同一方向，那是吉他 (拾音器) 和原錄音不同造成的，應該在全域補償一次，而不是每個 Patch 各改一次。

### 信心值

每個偵測器都回傳 0~1 的 confidence，報告上顯示為高 (≥ 0.7) / 中 (≥ 0.45) / 低。它反映的是「證據有多充分」(例如殘響量到幾段尾音、延遲峰值有多突出)，不是統計意義上的機率。

## 使用建議與限制

- **最準：單獨的吉他音軌** (分軌、Guitar Pro 匯出、或 solo 段落)。完整混音中有鼓/貝斯/人聲時，EQ、破音、殘響會受影響。
- 有「停頓 / 切音 / 結尾餘音」的片段，殘響才量得準。
- 有明顯延遲時，殘響長度無法與延遲回授分開，報告會標示「可能有」並給保守值。
- 一個 Patch 只有一個 MOD 與一個 EFX block；同時偵測到多種調變時，報告會說明取捨。
- 標示「≈」的 RATE / DECAY 等數值是近似換算，請以機器畫面與耳朵為準。
- 最有效的流程是「分析 → 照設定錄音 → `--compare` → 修正」重複 1~2 次。

## 測試

```bash
python make_test_audio.py   # 合成 9 個已知效果的測試音檔到 test_audio/
python run_tests.py         # 對每個音檔跑分析，印出偵測到的參數與推薦型號
```

`make_test_audio.py` 用加法合成撥弦 (含弦的非諧性與撥弦雜音) 組成 8 小節樂句，每 2 小節切音一次好讓殘響可以量測，再套上已知參數的破音、延遲、殘響、Tremolo、Chorus、Phaser、哇音。拿已知答案去驗證偵測器，是調整各個門檻的依據。`test_audio/` 已在 `.gitignore` 中，clone 後自行產生即可。

## 檔案

- `mg30_tone.py`：主程式 (CLI 與 Markdown / JSON 報告)
- `features.py`：音訊特徵分析 (上面「原理」1~11 節)
- `recommend.py`：特徵 → MG-30 設定 (第 12 節)
- `calibrate.py`：比對校正與吉他拾音器建議 (第 13 節)
- `mg30_db.py`：MG-30 全部型號與參數 (韌體 4.x / V5 清單，附 GEN2 差異)
- `make_test_audio.py`、`run_tests.py`：合成已知效果的測試音檔並驗證偵測結果
- `requirements.txt`、`requirements-optional.txt`：相依套件 (後者加上 ffmpeg 以支援 m4a / aac / mp4)
